# v0.16.0 — Auditoría visual completa del frontend

**Estado del documento**: snapshot pre-v0.16.1, generado en investigación pura
(read-only, sin modificar código). Documenta el inventario del design system
**antes** de la refundación de foundations que se hizo en v0.16.1.

**Vigencia post-v0.16.1**: el bloque `:root` y `[data-theme="light"]` ya
fueron refactorizados (tokens semánticos + aliases legacy). El resto del
inventario (40 font-sizes, 52 botones, 30 cards, iconografía mezclada,
hardcoded `#f97316` × 60, ~100 overrides ad-hoc en light, etc.) **sigue
vigente** porque ningún componente ha migrado todavía. Esa migración
ocurre en v0.16.4-9.

**Contexto estético objetivo**: Linear / Vercel / Cursor — minimalismo
oscuro elegante, tipografía fuerte, color contenido como acento.

**Archivo analizado**: `templates/index.html` (~21 345 líneas, ~2 145
selectores de clase, CSS y HTML en el mismo archivo).

## 0.1 — Design tokens actuales (pre-v0.16.1)

**Localización única**: bloque `:root` y `[data-theme="light"]` al inicio
del archivo, seguido de ~100 overrides ad-hoc del tipo
`[data-theme="light"] .X { ... }` (estilando componentes individuales en
light en lugar de derivarlos de tokens).

**Tokens definidos** (estado pre-v0.16.1):

| Categoría | Token | Dark | Light |
|---|---|---|---|
| Background | `--bg` | `#07080b` | `#f0ede8` |
| Surface | `--surf` / `--surf2` | `#1c1f29` / `#262a36` | `#f7f5f1` / `#eae7e1` |
| Border | `--border` | `rgba(255,255,255,.10)` | `rgba(0,0,0,.08)` |
| Texto | `--text` / `--text2` / `--text3` | `#f1f3f7` / `#8b92a5` / `#9298a6` | `#0a0a0a` / `#555` / `#777` |
| Brand | `--brand` / `--brand-cta` | `#f97316` / `#c2410c` | (mismos) |
| Otros | `--pink` (`#FBBF24`), `--green` (`#22c55e`) | | |
| Gradientes | `--grad`, `--grad2` | naranja→amarillo / naranja→naranja oscuro | (mismos) |
| Sombras | `--sh`, `--sh-lg`, `--glow` | dark | overrides en light |
| Radii | `--r: 14px`, `--rsm: 8px` | | (mismos) |
| Fuentes | `--font-display: 'Instrument Serif'`, `--font-body: 'DM Sans'` | | |
| Spacing | `--space-xs/sm/md/lg/xl/2xl` = `6/10/16/24/32/48px` | | |

**Hueco grande**: no había tokens semánticos (success, warning, error,
info) ni escala de gris (sólo 3 niveles de texto + 2 surfaces). `--pink`
mal nombrado (es amarillo `#FBBF24`). Tokens de radius solo 2, faltaban
`--r-xs`, `--r-pill`. Sin tokens de transición ni de z-index.

**Estado dark/light**: ambos definidos. Toggle vía
`document.documentElement.setAttribute("data-theme", X)`. Auto-detect
inicial vía `prefers-color-scheme: dark`. **Soporte light real, pero
implementado por override-explícito clase-a-clase, no derivado**.

## 0.2 — Tipografía

**Carga (pre-v0.16.1)**: Google Fonts una sola request:
- `DM Sans` (body) — pesos 300, 400, 500, 600, 700 + italic 300
- `Fraunces` — cargada pero ya **no se usaba** en `:root`
- `Instrument Serif` (display)
- `JetBrains Mono` — cargada pero solo usada como fallback en 1 sitio

**Tamaños font-size: 40 valores únicos**. Rango: `.55rem` a `1.4rem+`.
**Sin escala** — incrementos arbitrarios:

+ `font-weight:300` aparece **inline 7 veces**.

**line-height: 20 valores únicos**

## 0.5 — Spacing y layout

**Tokens** `--space-xs/sm/md/lg/xl/2xl` (6/10/16/24/32/48px). Existían
pero **uso disperso**. Mucha métrica continuaba hardcodeada
(padding/margin con valores tipo `8px`, `12px`, `14px`, `20px` que no
encajaban en la escala). (v0.16.1 introdujo escala completa 4px-base
de 17 niveles, manteniendo los viejos como aliases.)

**Grid**: cero sistema. Cada panel se montaba con `display:flex` o
`display:grid` inline o local.
`grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))` aparece
varias veces — patrón de "grid de cards responsive" reinventado en cada
panel.

**Breakpoints**: **15 puntos de corte distintos**:

```
360, 420, 480, 520, 540, 560, 620, 640, 700, 768, 820, 880, 900, 980, 1024 px
```

Mezcla `max-width` (la mayoría) + `min-width` (4 casos). **Sin sistema
de breakpoints definido**.

`@media (prefers-reduced-motion: reduce)` sí existía (defensa
accesibilidad).

## 0.6 — Iconografía

**Mix de tres sistemas**:

1. **SVG inline**: ~95 `<svg>` en el archivo. Estilo "outline 1.5px
   stroke" en sidebar/avatar (pixel-art `shape-rendering="crispEdges"`
   en algunos iconos del nav profile). **Sin librería**, totalmente
   custom.
2. **Emojis** abundantes: 📝 ✨ 💡 🎬 🔥 😂 📖 🎣 ★ ✓ ▾ ✕ × en cards de
   competidores, ideas, asistentes. **Inconsistente** con los SVG
   outline del nav.
3. **Mascota pixel-art** propia (Hooks) en `static/img/hooks/*.svg` para
   empty states.

**Coexisten 3 estéticas** — outline minimalista (nav), emoji color
OS-render (cards) y pixel art (mascota). Esto es un anti-Linear/Vercel:
ellos usan **una librería única** (Tabler/Lucide), monocroma, sin emojis
nunca. (Decisión saga: migrar a Tabler Icons en v0.16.3.)

## 0.8 — Estado dark/light

**Sí había soporte light real**:
- Token block `[data-theme="light"]` con 6 tokens overridden.
- ~100 overrides explícitos de clase específica en light — más light
  por componente que por token derivado.
- Toggle: JS + matchMedia `prefers-color-scheme` para init.
- localStorage `rs-theme` con 3 estados (`light`|`dark`|`system`).
- Segmented control con 3 botones (light/system/dark).

**Cambios estructurales para refactor v0.16.1+**:

1. **Mover los 100 overrides ad-hoc** dentro de `[data-theme="light"] .X`
   a tokens derivados: el componente debe leer `var(--surface-raised)` y
   que el TOKEN cambie según `data-theme`, no el componente. (Pendiente
   v0.16.4-9 al migrar cada panel.)
2. **Definir tokens semánticos** que se intercambien entre themes
   (`--success`, `--success-bg`, `--success-fg`, etc.) en lugar de
   hardcoded colors verdes/rojos. **(Hecho en v0.16.1.)**
3. **Estandarizar el toggle**: una sola función `toggleTheme()` con
   persistencia localStorage. El init ya lo hacía bien (data-theme HTML
   attribute).

# Sumario ejecutivo

## 5 problemas más graves del design system actual

1. **No hay primitivos compartidos** (`.btn`, `.card`, `.chip`, `.field`).
   52 clases de botón + 30 de card + 25 de chip todas inventadas ad-hoc
   por feature. Cualquier cambio de estilo "global" requiere editar N
   sitios. Es el cuello de botella raíz de todos los demás problemas.

2. **Brand hardcoded** (`#f97316` × 60, `#c2410c` × 28). El token
   `--brand` existe pero solo se usa parcialmente. Cambiar el brand
   requeriría find-and-replace masivo.

3. **Tipografía sin sistema**: 40 font-sizes únicos, 20 line-heights, 6
   weights cargados (probablemente 3 son innecesarios). Resultado
   visual: caos sutil entre cards similares.

4. **Iconografía mezclada**: emojis (📝 ★ 💡) en cards + SVG outline en
   sidebar + pixel-art mascotas. Imposible alcanzar la estética
   Linear/Vercel sin unificar a una sola librería monocroma.

5. **Light mode implementado por overrides explícitos clase-a-clase**
   (~100 reglas `[data-theme="light"] .X`) en lugar de derivar todo de
   tokens. Frágil — cualquier componente nuevo olvidará el override de
   light y se romperá.

## 5 oportunidades más altas

1. **Unificar a Tabler Icons** (o Lucide). Una sola librería, monocroma,
   stroke 1.5px. Reemplaza emojis y SVG custom. Cambio puramente visual
   masivo, ~1 día de trabajo.

2. **Establecer escala tipográfica de 8 sizes**
   (`--font-xs/sm/base/lg/xl/2xl/3xl/4xl`) y cargar **solo 3 weights**
   (400/500/700). Reduce 40 font-sizes a 8, paso de 6 weights a 3
   (ahorro bandwidth ~30%).

3. **Primitivos**: `.btn` con variantes `.btn-primary`, `.btn-secondary`,
   `.btn-ghost`, `.btn-danger`, tamaños `.btn-sm`, `.btn-md`, `.btn-lg`.
   Mismo para `.card`, `.chip`, `.field`. Migración incremental por
   panel. Reduce CSS al menos 30-40%.

4. **Tokens semánticos completos**: `--success-fg/bg/border`,
   `--danger-fg/bg/border`, `--warning-*`, `--info-*` + escala de gris
   50-900 + `--text-primary/secondary/tertiary`. Refactor del light/dark
   a "swap tokens, no override clases".

5. **Inventory de paneles**: cada uno necesita un audit individual para
   alinearlo al nuevo sistema. Overview, Ideas y Scripts son los 3 con
   más densidad visual y donde más impactará un rediseño Linear-like.

## Propuesta de scope v0.16.1

**Fase A — Foundations (1-2 días)**:
- Nuevo `:root` con tokens semánticos completos: brand-50/100/.../900,
  gray-50/.../900, success/danger/warning/info en 3 niveles
  (bg/fg/border), espaciado (xs/sm/md/lg/xl/2xl/3xl), tipografía (8
  sizes + 3 weights), radii (xs/sm/md/lg/full), shadows (sm/md/lg/xl),
  z-index escala.
- `[data-theme="light"]` reescrito como **swap puro de los tokens
  existentes**, sin overrides de clase.
- Reducir Google Fonts a `DM Sans 400/500/700` + `Instrument Serif 400`
  (~30% ahorro).
- Sustituir `JetBrains Mono` (no se usa) por
  `font-family: ui-monospace` sistema.

**Fase B — Primitivos (2-3 días)**:
- `.btn` base + 4 variantes × 3 tamaños = 12 estados controlados.
- `.card` base + variantes (`-elevated`, `-flat`).
- `.chip` / `.badge` / `.pill` unificados con `.tag` (¿o mantenidos
  como 2 primitivos: tag visual + status badge?).
- `.field` para input/textarea/select con label, helper text, error
  state.
- Iconografía: Tabler Icons inline (preferible) o como sprite SVG.
  **Cero emojis en UI** salvo donde sean parte del contenido del user.

**Fase C — Migración incremental panel a panel (5-7 días)**:
- Orden: **Overview → Ideas → Scripts → Transcribir → Métricas →
  Assistants → Settings**.
- Cada panel: reemplazar sus clases ad-hoc por primitivos, eliminar
  overrides redundantes, audit visual side-by-side.
- Las clases viejas se mantienen en CSS deprecated hasta que cada panel
  migre. Después se borran.

**Orden de prioridad si hay que recortar**:
1. **Foundations + tokens** son no negociable — sin esto no avanza
   nada.
2. **Botón base** (`.btn`) es el primitivo con más impacto visible —
   pínchalo primero.
3. **Iconografía** (Tabler) es el mayor "wow visual" — segundo en
   valor percibido.
4. **Cards** después — más invasivo pero menos transformador.
5. Inputs/chips/badges al final — son menos visibles.

**Anti-objetivos v0.16.1** (no perder tiempo aquí):
- Refactor de la landing pública (`#heroRotator`, `.hero-*`) — distinto
  contexto estético, atacar en v0.17 o aparte.
- Mobile responsive completo — la migración a primitivos lo arrastra
  naturalmente; no hacer pasada extra.
- Animaciones/microinteractions — capa siguiente, no foundational.

**Riesgo principal**: las 450 estilos inline en HTML van a sobrevivir a
la migración CSS si no se atacan explícitamente. Hay que decidir si
entran en scope de v0.16.1 o quedan como deuda v0.16.2+.
